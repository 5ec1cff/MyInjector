# 哔哩哔哩界面版本

设置新增「界面版本」分组，每项独立提供「不强制」「强制新版」「强制旧版」。
保存后重启哔哩哔哩生效，其他普通功能开关保持原来的实时生效方式。
可从宿主「MyInjector 设置」或模块 App 的「应用内设置」进入。

除分享框架保留原来默认强制新版的行为外，其余组件默认不强制。
旧 JSON 的 `forceNewShare=true` 或缺省迁移为分享强制新版，`false` 迁移为不强制，
不会把旧的关闭状态解释为强制旧版。明确保存的新选项优先，之后不再写旧字段。

## 组件和选择点

以下选择点已用 9.19.0 APK 核对，混淆类名通过 DexKit 定位，不写入 Hook 的匹配条件。

| 组件 / JSON 子键 | 选择点 | 处理方式 |
| --- | --- | --- |
| 分享框架 / share | `ff_share_kt_imp` 的最终布尔入口 | 复用原有分享框架定位，覆盖返回值 |
| 视频详情 / video | `kmp_theseus`，值为 `new` 时选择 Theseus2 | 覆盖字符串配置及最终布尔入口，旧版为 Theseus |
| 搜索主页面 / search | `using_cmp_search_module` | 控制普通搜索入口重定向到 `bilibili://ksearch` |
| 搜索子页面 / searchSubpage | `using_cmp_search_module_subpage` | 单独控制番剧聚合、漫画和选集等子页面 |
| 图文详情 / opus | `following.opus_detail_use_cmp` | 控制原生详情到 CMP 详情的重定向 |
| 关注信息流 / following | `following.following_list_use_cmp` | 控制底栏关注页创建原生列表还是 CMP 根 Fragment |
| 历史记录 / history | `history.history_use_cmp` | 控制历史入口到 CMP 历史的重定向 |
| 开屏框架 / splash | `dd_splash_business_use_cmp_exp` | 同时处理框架选择和资源工厂的配置读取 |
| 我的页面 / mine | `dd.wide_mine_v2` 和设备类型判断后的最终 Lazy | 按这个 Lazy 的实例覆盖最终值，可在手机上测试 V2 |
| 评论框架 / comments | `comment.kntr.enabled`、`comment.kntr.route.enabled`、`comment.kntr.story.enabled`、`comment.kntr.landscape.enabled` | 一个选项统一控制普通评论、路由、竖屏和横屏场景；旧版仍可能使用 comment2 或 comment3 |

入口位于 `BiliInterfaceVersions.install`，在其他业务 Hook 加载之前安装。
普通配置经过 `DeviceDecision.getBoolean`，Kotlin 配置经过 `IDeviceDecisionKt.getBool/getString`
及其默认参数入口；只修改表中的键。开屏资源工厂还直接使用 `GDeviceDecision`，
在工厂开始执行时为实际实例安装同样的键过滤。
读取方法及最终选择入口的调用方做去优化，避免 ART 已有内联跳过 Hook。

「我的」页面不能只把 `dd.wide_mine_v2` 改成 true：宿主还会判断设备类型。
它的配置 lambda 被 R8 合并，不能覆盖整个 `invoke`；这里仅在读取目标 Lazy 实例时改值。
所有卸载句柄交给 `BiliHandler` 管理。

## 实际版本显示

每项分别显示三类信息：

- 已保存：JSON 中的选项。与本次加载的快照不同会提示待重启，并列出本次使用的选项。
- 实际页面：本次进程实际创建或渲染过的页面版本。未进入对应路径时显示未观测；
  同一进程使用过两套页面时显示两者均已观测。
- 入口选择：宿主实际读取到的选择结果，与页面观测分开记录。没有读取时显示未观测，
  不主动执行配置 getter，也不根据强制选项推算页面版本。

原生页面通过 Activity 和 Fragment 生命周期记录，CMP 页面通过各自的渲染入口记录。
新版视频在 Theseus2 业务组件启动时记录；旧版分享在原生分享调用栈中的 Dialog 确实显示时记录。
搜索子页面使用漫画、聚合、选集各自的入口，不把普通搜索内部名为 `SearchSubPage` 的组件
误认为独立的搜索子页面。

观测和错误只保留在本次进程，重新打开设置会重新读取当前记录；不写入配置文件。
定位、安装或运行时发生错误时，对应设置项标记「存在问题」，沿用现有的查看、复制和分享错误功能。

## 作用范围

这些选项用于测试宿主已有的切换点，不更改所有显式指定版本的内部地址。
半屏搜索保留宿主原有的兼容分支；从卡片在新任务打开图文时，原有实现直接创建原生 Fragment
容器，会绕过 CMP 重定向，因此可能出现入口选择新版、实际页面旧版的记录。
直接进入 CMP 地址也可能绕过旧版选择。这些情况不会把已保存的强制选项当作页面观测结果。

开屏广告净化可能阻止开屏内容显示，此时入口选择已有结果，而页面仍未观测是正常的。
强制切换框架不自动为原本只适配某套框架的模块功能补齐另一套实现。
首页卡片的新旧渲染和菜单分支还不等于已确认的整页版本开关，本组没有新增虚假的首页总开关。

## 验证

配置测试覆盖三种模式独立保存、旧分享开关迁移、显式新配置优先及非法字段处理。
状态测试覆盖保存后不改变本次快照、未观测状态、选择与实际页面不一致、同时出现两套页面
以及组件之间的错误隔离。另用实际 9.19.0 APK 检查最终选择点和 CMP 渲染入口的定位。
Debug、Release 构建通过，83 项测试通过；另 1 项依赖 9.17 旧样本的检查跳过。
用户实测可强制使用新版或旧版。已有模块功能在不同框架下仍存在兼容问题，
本次提交只包含版本控制和观测功能，具体兼容问题后续单独修复。

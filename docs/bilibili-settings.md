# 哔哩哔哩应用内设置

从哔哩哔哩「我的」页面，点击原生「设置」前面的「MyInjector 设置」打开弹窗。
也可以从模块 App 的应用列表打开哔哩哔哩的「应用内设置」。弹窗使用与小红书相同的
`SettingDialog` 和设置组件，普通启动不自动显示设置。
模块首页通过 `ScopeCatalog.settingsApps` 决定是否显示按钮，已登记 `tv.danmaku.bili`。

## 「我的」页面入口

参考 BiliRoaming 的 `SettingHook`，向宿主菜单模型插入独立菜单项，复用原生设置项的图标和样式。
入口没有功能开关，关闭全部增强功能后仍然可以打开设置和查看错误。

针对 9.19.0 中保留的两套「我的」页面分别处理：

- 旧版 RecyclerView：菜单构建结束后，在与 Adapter 共用的菜单组中插入入口；在原生点击分发之前
  按自定义 URI 接管点击，不需要为入口注册宿主业务代理。
- 新版 Compose：读取 `MenuGroupV2.getItemList` 时返回插入入口的列表副本，兼容服务端下发和宿主
  本地补出的设置项；在默认菜单路由方法中接管自定义 URI。

两条路径都检查自定义 URI，刷新页面不重复插入，不覆盖 View 点击监听器。
混淆方法与字段通过 DexKit 定位并缓存；两套入口独立安装，定位和运行错误归入「设置与初始化」。
Release 编译通过，用户已验证设置入口可用。

## 开关与生效方式

全部开关默认开启，修改后对新页面和后续操作生效，无需重启。
不主动刷新已打开的页面、菜单或正在显示的广告。

| JSON 键 | 功能 | 生效时机 |
| --- | --- | --- |
| betterShare | 复制原始分享链接，包含新旧分享处理 | 下一次生成分享内容或执行复制 |
| forceNewShare | 固定新版分享框架 | 下一次创建分享框架，部分页面需要重新打开 |
| copyCommentLink | 评论菜单复制直达评论链接 | 下一次打开评论菜单 |
| commentLinkInVideo | 视频评论链接在视频页内定位 | 下一次处理评论链接跳转 |
| showAv | 视频详情显示 AV 号 | 新页面或后续标题渲染 |
| replaceStoryVideo | 替换竖版视频为普通详情页，关闭自动进入 Story | 下一次路由跳转或读取自动 Story 配置 |
| viewSubtitles | 视频菜单查看字幕 | 下一次构建视频菜单 |
| viewCover | 视频菜单查看封面 | 下一次构建视频菜单 |
| openVideoInNewTask | 视频和图文详情、首页与关注信息流、底部推荐和视频搜索在新任务打开；竖屏视频走普通详情页 | 新图文页面或下一次构建对应菜单 |
| newTaskBackgroundPlay | 独立任务视频切入 App 内其他任务后继续后台播放 | 后续跨页面回调，仍需开启宿主后台播放 |
| purifySearch | 净化搜索页面，移除热搜、推荐及默认推荐词 | 后续加载搜索页、推荐或默认词；无需重启 |
| removeUnderPlayerAd | 移除播放器下方广告 | 后续广告渲染回调 |
| removePauseAd | 移除暂停广告 | 后续广告资格判断或新视频页 |
| removeFreeDataGuide | 移除免流套餐推广 | 后续免流引导流程 |
| removeCloudTvOverlay | 移除云视听推广角标 | 新的弹幕活动响应 |
| removeSplashAd | 移除冷、热开屏广告 | 下一次开屏流程 |

固定新版分享与原链接复制互不绑定；关闭固定新版后回到宿主自己的灰度结果，不强制旧版。
字幕、封面和新任务按钮分别控制，全部开启时依次为「查看字幕」「查看封面」「在新任务打开」，
开关关闭后不再向新菜单插入对应按钮。
「在新任务打开」和「独立任务后台播放」归入独立的「多任务视频播放」分类。
列表长按入口与详情页入口共用 `openVideoInNewTask`，点击列表菜单后保留原列表页面。
关注信息流的卡片右上角三点菜单也由此开关控制，修改后下次打开菜单生效。
图文详情顶部增加仅显示图标的入口，新版放在分享按钮左侧，原生 Fragment 页放在更多按钮左侧；
修改开关后新页面生效。点击后在新任务重开当前图文，启动成功后结束原 Activity。
「广告与推广 → 净化搜索页面」兼容新旧搜索页，保留历史、输入联想和正常搜索结果，详见
[实现说明](bilibili-purify-search.md)。修改后不主动刷新已打开的搜索页；关闭后后续加载恢复宿主内容，
已变为空内容的内存状态需要重新加载。
广告类关闭后放行后续原生流程，不补回已经拦截的广告或已经过滤的活动数据，
也不绕过宿主自己的缓存和频控。

### 实现方式

所有功能的 Hook 在启动时注册，回调从当前配置读取开关。
配置确认写入成功后，通过 volatile 字段发布给后续回调。
不在切换时卸载 Hook，已经显示的自定义菜单项、已开始的点击操作仍保留对应处理。
评论菜单即使关闭也保持成对的调用范围清理，避免嵌套渲染误用上一条评论。

字幕服务关联在开关关闭时也继续记录，以便重新开启后读取当前播放器的字幕。
字幕菜单过滤、自定义点击和封面保存按钮处理保持可用，只在构建新菜单时检查是否插入入口。

## JSON 配置

配置保存在哔哩哔哩自身数据目录的 `my_injector_settings`，内容是扁平 JSON：

```json
{"betterShare":true,"forceNewShare":true,"viewSubtitles":false,"viewCover":true}
```

未出现或类型无效的字段使用默认值，未知字段忽略。不新增 protobuf 配置，也不迁移或修改其他
Handler 的配置格式。整个 JSON 无法读取或解析时，本次启动使用默认值，并记录读取错误。

使用 Android `AtomicFile` 写入，失败时保留旧文件。由于 `finishWrite` 对部分提交失败只写日志，
写完后读回核对内容，成功才接受界面的新开关状态，失败则提示用户并保留原状态。
源码依据：[AOSP AtomicFile.java](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/core/java/android/util/AtomicFile.java#L172)。

## Hook 错误汇报

安装、定位及运行时回调错误按功能和出错阶段保存，同时继续写入 logcat。
设置项会标出「存在问题」，下方出现「查看错误」，支持查看完整堆栈、复制和系统分享。
报告包含模块版本、宿主版本和当前进程。仅用户点击分享时打开系统分享面板，不自动发送。

记录只保留当前进程本次加载以来的错误，不持久化堆栈；应用重启或模块热重载后重新记录。
字幕下载失败等正常业务错误仍由字幕界面提示，不作为 Hook 定位错误汇报。

设置入口 Hook 将每个卸载句柄交给 BiliHandler 管理，热重载时与功能 Hook 一并释放，防止旧弹窗入口叠加。

## 设置功能的既有验证

Debug、Release 构建通过。JVM 测试 67 项通过，6 项需要外部 APK / 主机 DexKit 的可选检查跳过。
配置测试覆盖默认行为、各开关独立往返保存、未知字段和无效字段兼容。
同时补齐两处原有测试断言遗漏的 GMS FCM 配置键和总数，未修改该选项的生产实现。

在自行启动的独立 Android 15 模拟器实例中，使用实际 BiliSettingsDialog 验证：

- 设置弹窗及搜索正常，封面开关关闭后 JSON 的字幕开关仍为 true，重新启动测试进程后回显正确。
- 注入测试错误后对应设置项标红，错误详情、复制与系统分享面板正常。
- 模拟 AtomicFile 写入失败时，界面拒绝切换且原 JSON 保留。
- JSON 损坏时恢复默认配置，并在错误详情中报告读取失败。
- 模块首页搜索哔哩哔哩后显示「应用内设置」，点击后传给打开设置回调的包名为 `tv.danmaku.bili`。
